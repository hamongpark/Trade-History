# Trade-History: 기획 초안 (v0)

> 목적: 매일의 매매 기록을 **모바일에서 빠르게 저장**하고, 쌓인 기록으로 **내 매매 스타일·장단점·개선점**을 찾는다.
> 상태: 초안 — 아래 "결정 필요 항목"이 답변되면 PRD / TRD / UI 문서로 쪼갠다.

---

## 1. 요청한 기능 (MVP 범위)

| # | 기능 | 비고 |
|---|------|------|
| 1 | 매매 기록 저장 | 티커, 분 단위 매수/매도 시각, 매수가/매도가, 손익, 매수/매도 사유 |
| 2 | 매매 스타일 파악 | 누적 통계 기반 |
| 3 | 장단점·개선점 | 통계 + 규칙 기반 진단 (+ 선택적으로 AI 코멘트) |
| 4 | 체결 시점 ±30분 분봉 + 거래량 차트 | 매수·매도 마커 표시 |

## 2. 추가 제안 기능 (실제 매매 개선에 효과가 큰 순)

### A. 기록 단계에서 꼭 넣어야 할 것 (나중에 추가하면 과거 데이터가 비어서 분석 불가)

1. **계획 손절가 / 목표가** → R-multiple(손실 대비 몇 배 벌었나) 계산의 기반. 손익금액보다 훨씬 공정한 비교 지표.
2. **셋업 태그** (예: 돌파, 눌림목, 갭상승, VWAP 반등, 뉴스) → "어떤 셋업에서 돈을 버는가"가 가장 실용적인 분석.
3. **사유를 자유 텍스트 + 태그로 이원화** → 텍스트는 복기용, 태그는 통계용.
4. **감정/상태 태그** (FOMO, 복수매매, 확신, 지루함 …) + **확신도 1~5**.
5. **계획 준수 여부** (진입·청산이 계획대로였나 Y/N) → 규칙 위반 비용 측정.
6. **분할 매수/매도 지원** → 1개 포지션 = 여러 체결(execution). 처음부터 이 구조가 아니면 나중에 마이그레이션이 고통스러움.
7. **수수료·세금** → 순손익 기준 분석.
8. **스크린샷 첨부 (선택)** → 당시 호가창·차트 캡처.

### B. 분봉 데이터를 활용한 분석 (이 툴의 차별점)

- **MAE / MFE**: 보유 중 최대 역행폭 / 최대 순행폭 → "손절이 너무 넓은가", "익절이 너무 이른가"를 숫자로 보여줌.
- **매도 후 추이 (Exit efficiency)**: 매도 후 30분간 최고/최저가 대비 내 매도가 위치 → 조기 익절 습관 진단.
- **진입 타이밍 품질**: 진입 직전 N분 상승률(추격매수 여부), 거래량 급증 대비 진입 시점.
- 차트 오버레이: 매수/매도 마커, 손절·목표선, VWAP, 이동평균(5/20).

### C. 통계 대시보드

- 기본: 승률, 평균 이익/평균 손실, Profit Factor, 기대값(Expectancy), 최대 낙폭(MDD), 누적 손익 곡선.
- 분해 분석: **시간대별**(장초 30분 vs 이후), 요일별, 보유시간별, 셋업별, 종목별, 감정태그별 성과.
- 행동 패턴 탐지:
  - 과매매: 하루 매매 횟수 vs 그날 손익
  - 복수매매: 손실 직후 N분 내 재진입의 성과
  - 연승/연패 후 성과 변화
  - 손실 포지션 보유시간 > 이익 포지션 보유시간 (손실 버티기)

### D. 복기·습관 루프

- **일일 저널**: 장전 계획 / 장후 복기 / 시장 분위기 태그.
- **나만의 매매 규칙 체크리스트**: 예) "장초 5분 매수 금지", "일 손실 -X원 시 종료" → 위반 횟수와 위반 시 손익 추적.
- **주간 리포트 (AI 요약, 선택)**: 누적 데이터 + 사유 텍스트를 LLM에 넣어 "이번 주 반복된 실수 / 잘한 점 / 다음 주 집중할 1가지" 생성.

## 3. 기술 방향 (추천안)

- **형태**: 모바일 우선 **PWA 웹앱** (홈화면 설치, 앱스토어 불필요, PC에서도 동일하게 사용).
- **프론트**: Next.js(React) + Tailwind, 차트는 TradingView **lightweight-charts** (모바일 터치 성능 우수, 무료).
- **백엔드/DB**: Supabase (Postgres + 인증 + 파일 저장) — 1인 사용이면 무료 티어로 충분.
- **배포**: Vercel.
- **분봉 데이터**: 시장에 따라 결정 (아래 질문 참고). **중요**: 대부분 무료 API는 과거 1분봉 보관 기간이 짧음 → 기록 시점에 ±30분(또는 장 전체) 분봉을 **받아서 DB에 캐싱**하는 구조로 설계.
- **AI 분석(선택)**: Claude API로 주간 리포트 생성.

### 데이터 모델 초안

```
positions      id, ticker, market, side(long/short), opened_at, closed_at,
               planned_stop, planned_target, setup_tags[], emotion_tags[],
               confidence, followed_plan, entry_reason, exit_reason,
               gross_pnl, fees, net_pnl, r_multiple, mae, mfe, note
executions     id, position_id, action(buy/sell), executed_at(분), price, qty, fee
candles_1m     ticker, market, ts, open, high, low, close, volume   (캐시)
daily_journal  date, premarket_plan, review, market_mood, rules_broken[]
rules          id, text, active
tags           id, type(setup/emotion/mistake), name
```

## 4. 결정 필요 항목 (PRD/TRD/UI 작성 전 확인)

### PRD (무엇을)
1. 대상 시장: 국내주식 / 미국주식 / 둘 다 / 코인?
2. 사용 증권사 (체결내역 자동 가져오기 가능성 판단용)
3. 매매 스타일: 스캘핑 / 데이트레이딩 / 스윙? (±30분 창이 적절한지)
4. 분할 매수·매도, 공매도 여부
5. 하루 평균 매매 건수
6. 입력 방식: 수동 입력 / 증권사 CSV 업로드 / 증권사 API 자동 동기화
7. 위 2장의 추가 제안 중 MVP에 넣을 것
8. AI 주간 리포트 사용 여부 (API 비용 발생)

### TRD (어떻게)
9. 형태: PWA 웹앱(추천) / 네이티브 앱 / 구글 시트 기반
10. 사용자: 본인 1인 전용 / 향후 다른 사람도 사용
11. 분봉 데이터 소스와 예산 (무료 우선 / 월 수만원 이내 유료 API 가능)
12. 데이터 백업·내보내기(CSV/엑셀) 필요 여부

### UI (어떻게 보이게)
13. 기록 화면: 한 화면 폼 vs 단계별(체결 → 사유 → 태그) 입력
14. 홈 화면에 먼저 보고 싶은 것: 오늘 손익 / 캘린더 손익 히트맵 / 최근 매매 리스트
15. 다크모드 기본 여부, 손익 색상 (국내식 빨강=이익 vs 미국식 초록=이익)
